## Current release checks

- `dotnet test backend/Qbc.Workboard.slnx --configuration Release`: 31 passed, 0 failed across API and CLI integration tests.
- `npm run test:e2e`: 130 passed, 0 failed in 1.9 minutes — 98 Chromium scenarios plus the 16-test `@smoke` subset in each of Firefox and WebKit. The isolated suite starts neither .NET nor SQL Server; it was verified with no listener on the API port. `--repeat-each=2` passes 196, so no scenario depends on another.
- `npm run typecheck:e2e`: passed with the mock API, fixture, specifications, Page Objects, and Playwright configuration checked under the workspace's strict TypeScript rules.
- `dotnet publish backend/src/Qbc.Workboard.Api/Qbc.Workboard.Api.csproj --configuration Release --output artifacts/publish`: succeeded; a production smoke test returned HTTP 200 for the Angular `/board` fallback and the workspace API.
- Backend integration tests use a separate named SQL Express database per test class and invoke the real ASP.NET Core controller, MediatR, validation, EF Core, and Problem Details path.
- Browser specifications contain scenario intent only; selectors, navigation, interactions, and assertions are owned by Page Objects, while the auto fixture owns the shared API interception boundary.
- Every browser test receives fresh in-memory API state that survives reloads within the scenario, shaped by a named `seed` scenario where the Given clause needs it. Unhandled `/api` requests fail the test, and the suite starts neither .NET nor SQL Server. Tests run with a workspace session already held unless they opt into `locked`, so the passcode gate is exercised deliberately rather than incidentally.
- Of the 147 Given/When/Then scenarios in `docs/specs/L2.md`, 90 are observable through a browser against a mocked API and each has one Playwright test. The remaining 57 get none: 40 describe code organisation or the ATDD process itself and are excluded by `L2-039`; 13 describe referential integrity, transactional rollback, Problem Details shape, credential issuance, passcode provisioning, or assembly-metadata version reads, which backend integration tests own; 2 describe a client calling the API directly past the frontend; 1 needs a backend restart; and 1 is a documentation requirement.
- Package restore/build output is warning-free, production dependencies have no reported npm audit findings, and production publish produces one ASP.NET-hosted application.
