Theming

Light by default, dark from the OS or a switch, and room for brand themes, all by overriding semantic tokens.

WCAG 2.2 AAStatus: stable

Overview

  • Light is :root; dark is [data-theme="dark"] and the same block under prefers-color-scheme: dark unless the page forces light.
  • Each theme sets color-scheme so native controls follow.
  • The mocks had no dark theme; it is built from the roles, not by inverting light.

Primitive--palette-green-600Semantic tokens only
Semantic--color-accentComponents and pages; themes override these

How dark is built

  • Surfaces lighten as they rise: canvas --palette-gray-950 < surface 900 < raised 800.
  • Accent lightens to green-300 and text on accent flips to deep green.
  • Status backgrounds are deep tints with light text.
  • Shadows use black at 40–60%.

Adding a theme

[data-theme="partner"] {
  --color-accent: var(--palette-blue-600);
  --color-fg-accent: var(--palette-blue-700);
}
  • Override semantic tokens only.
  • Add pairs to contrast-pairs.json and run the checker.
  • Never override primitives inside a theme.

tokens.json

tokens/tokens.json is a DTCG export generated from tokens.css ($type, $value, aliases as {group.token}, dark under $extensions). Use it to generate TypeScript or SCSS constants; never edit it by hand.

Do and don't

  • Do read var(--color-*) in components.
  • Don't write hex values outside tokens.css.
  • Don't detect the theme in script to pick colours.
