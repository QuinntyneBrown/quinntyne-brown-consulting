Accessibility

The WCAG 2.2 AA commitments every component meets, and how to check them.

WCAG 2.2 AAStatus: stable
  • Overview
  • Commitments
  • Interaction tokens
  • Testing procedure
  • Component contract
  • Tokens

Overview

  • Target: WCAG 2.2 AA in both themes.
  • Native elements first; ARIA patterns from the APG where native falls short.

Commitments

  • 1.4.3 / 1.4.11 contrast: text 4.5:1, control edges and focus 3:1, checked by check_contrast.py (108 pairs).
  • 2.4.7 / 2.4.11 focus visible: solid 2px ring with 2px offset on every interactive element.
  • 2.5.8 target size: ≥ 24px; 44px for primary touch targets.
  • 1.4.10 reflow: no 2D scroll at 320px.
  • 2.1.1 keyboard: every action, including drag and drop, has a keyboard path.
  • 2.2.1 timing: toasts pause on hover/focus; errors persist.
  • 2.3.3 / reduced motion: motion tokens collapse.
  • 3.3.1 / 3.3.3 errors: identified in text with a fix; summary on submit.
  • 4.1.2 name, role, value: every control named; states via aria-pressed, aria-expanded, aria-current, aria-invalid, aria-busy.

Testing procedure

  • Keyboard-only pass of every page and dialog.
  • Screen reader smoke test (NVDA + Chrome, VoiceOver + Safari).
  • Contrast checker in CI; axe on each page.
  • 200% zoom and 320px reflow.
  • Windows high contrast (forced colours).

Component contract

  • Every component page documents role, keyboard, focus, labelling, contrast, motion and touch under #accessibility.
  • A component without that section is not done.
