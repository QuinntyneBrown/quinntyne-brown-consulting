Button group

Groups related buttons. The segmented control picks one view from a few, like Write and Preview in the editor.

WCAG 2.2 AAStatus: stableNative HTML

Overview

  • Segmented switches between 2–4 views of the same thing (Write / Preview, Week / Month). One is always pressed.
  • Toolbar clusters formatting or bulk actions; buttons are independent.
  • Use tabs when the views are separate panels with their own content, and a select beyond four options.

Anatomy

  1. Track--color-bg-subtle, 2px inset, --radius-md.
  2. Pressed segmentSurface background, --shadow-1, default text.
  3. Unpressed segmentMuted text, transparent.

Variants

Segmented

Single select via aria-pressed.
HTML
<div class="segmented" role="group" aria-label="Editor view"><button class="btn" type="button" aria-pressed="true">Write</button><button class="btn" type="button" aria-pressed="false">Preview</button><button class="btn" type="button" aria-pressed="false">Split</button></div>

Toolbar

The editor toolbar: independent ghost buttons.
HTML
<div class="btn-group" role="toolbar" aria-label="Formatting"><button class="btn btn--ghost btn--icon btn--sm" type="button" aria-label="Bold"><b>B</b></button><button class="btn btn--ghost btn--icon btn--sm" type="button" aria-label="Italic"><i>I</i></button><button class="btn btn--ghost btn--icon btn--sm" type="button" aria-label="Code">{ }</button></div>

Sizes

Default 32px segments; small 28px for card headers.
HTML
<div class="segmented" role="group" aria-label="Small"><button class="btn" type="button" aria-pressed="true">Week</button><button class="btn" type="button" aria-pressed="false">Month</button></div><div class="segmented segmented--sm" role="group" aria-label="Extra small"><button class="btn" type="button" aria-pressed="true">Week</button><button class="btn" type="button" aria-pressed="false">Month</button></div>

Pointer and focus states are forced with data-state so they can be reviewed statically; product code gets them from real pseudo-classes and attributes.

Responsive behaviour

  • Segmented controls never wrap; with more than three segments below 360px, switch to a select.
  • Toolbars wrap onto a second row and keep their grouping.

Theming

The component reads semantic tokens only (listed under Tokens). The dark theme re-maps those tokens; nothing in the component changes.

Accessibility

Role and pattern

role="group" (segmented) or role="toolbar" with aria-label; each segment is a <button aria-pressed>.

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the control in DOM order.
Enter, SpacePresses the focused segment.
← →Toolbar only: moves between buttons (roving tabindex).

Focus

The shared ring (--focus-ring-width solid --color-focus-ring, --focus-ring-offset gap) appears on :focus-visible only. The mocks drew a 25% green halo (rgba(39,103,73,.25)) that measured 1.3:1; the system ring is solid and passes 3:1 (drift D2).

Labelling

The group label names the choice ("Editor view"); segment labels name each option.

Contrast

Pressed label
Unpressed label on track

Motion

No motion beyond colour transitions over --duration-fast, which the tokens zero under prefers-reduced-motion.

Touch

Controls are at least --control-height-md (40px) tall, above the 24px minimum; in dense rows the whole row is also a target and neighbours keep 8px apart.

Content

  • Segment labels are nouns or short adjectives: "Write", "Preview".
  • Keep labels the same length where possible so segments do not jump.
