Button

Buttons take an action: create a story, start a sprint, save, delete. One primary button per view says what matters most.

WCAG 2.2 AAStatus: stableNative <button>

Overview

  • Use a button when activation changes something: it submits, creates, deletes, opens a dialog or starts a process. Use a link to go somewhere.
  • Primary is the action the view exists for ("New story", "Start sprint", "Save story"). One per view.
  • Secondary is every other action ("Cancel", "Manage sprints").
  • Ghost lives in dense places: card actions, row actions, dialog close (the mocks' .quiet-button).
  • Danger confirms a destructive action and only appears inside a confirmation dialog ("Delete story").

Anatomy

  1. Leading icon (optional)20px, currentColor, aria-hidden.
  2. LabelVerb phrase in sentence case; the accessible name.
  3. Container--control-height-md tall, --radius-md, 1px border, --space-4 padding.

Variants

Variants change emphasis, not meaning.

Both themes

  • Loading keeps the width, hides the label behind a spinner, sets aria-busy and ignores clicks ("Save story" while the request is in flight).
  • Disabled is 52% opaque, as in the mocks. Prefer an enabled button that explains the problem on press.
  • Pressed (aria-pressed) is for toggles; see button group.

Responsive behaviour

  • Below 760px the page-head actions wrap under the title and keep their order; the primary stays first in the wrap.
  • Dialog footers stay on one row and wrap when narrower than their buttons; the primary is last.
  • Labels never truncate. A label that wraps at 360px is too long.

Theming

In dark the accent lightens to --palette-green-300 and the label flips to --color-fg-on-accent (deep green) so the pair stays above 7:1.

Component tokens: --btn-bg, --btn-bg-hover, --btn-bg-active, --btn-fg, --btn-border, --btn-height, --btn-padding, --btn-font-size. Each aliases a semantic token, so a theme re-colours the component by overriding semantic tokens and a product re-skin overrides the component tokens; neither edits the component CSS.

Accessibility

Role and pattern

Native <button> (type="submit" in forms). A link styled as a button is still an <a href>.

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the control in DOM order.
Enter, SpaceActivates the button.

Focus

The shared ring (--focus-ring-width solid --color-focus-ring, --focus-ring-offset gap) appears on :focus-visible only. The mocks drew a 25% green halo (rgba(39,103,73,.25)) that measured 1.3:1; the system ring is solid and passes 3:1 (drift D2).

Labelling

The visible label is the name. Icon-only buttons need aria-label with the object ("Edit QBC-269"), plus a tooltip. The mocks' close buttons used a bare "×" glyph; they now carry aria-label="Close".

Motion

Colour transitions over --duration-fast and a 1px press; the loading spinner keeps turning under reduced motion because it is a status, but every duration token drops to 0.01ms.

Touch

Controls are at least --control-height-md (40px) tall, above the 24px minimum; in dense rows the whole row is also a target and neighbours keep 8px apart.

Content

  • Verb phrases in sentence case: "New story", "Start sprint", "Log time", "Delete story". Never "OK" or "Submit".
  • Destructive labels name the loss: "Delete story", "Remove attachment".
  • Three words or fewer.
