File upload

Attach files to a work item by dropping them or choosing them.

WCAG 2.2 AAStatus: stableNative file input

Overview

  • The <input type="file"> is the control; the drop zone is an enhancement.
  • Each upload shows progress, then joins the file list.
  • Rejected files explain why (type, size) and offer a retry.

Responsive behaviour

  • Below 760px the drop zone shrinks to the button variant; phones rarely drag files.

Theming

The component reads semantic tokens only (listed under Tokens). The dark theme re-maps those tokens; nothing in the component changes.

Accessibility

Role and pattern

A labelled <input type="file">; progress uses role="progressbar"; completion and failure are announced in a polite live region.

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the control in DOM order.
Enter, SpaceOn "choose files": opens the picker.

Focus

The shared ring (--focus-ring-width solid --color-focus-ring, --focus-ring-offset gap) appears on :focus-visible only. The mocks drew a 25% green halo (rgba(39,103,73,.25)) that measured 1.3:1; the system ring is solid and passes 3:1 (drift D2).

Labelling

Remove and cancel buttons name the file ("Remove restaurant-list.xlsx").

Contrast

Motion

No motion beyond colour transitions over --duration-fast, which the tokens zero under prefers-reduced-motion.

Touch

Controls are at least --control-height-md (40px) tall, above the 24px minimum; in dense rows the whole row is also a target and neighbours keep 8px apart.

Content

  • Errors give the limit: "Too large: 140 MB. The limit is 25 MB."
  • Rules line lists accepted types in plain words.
