Skeleton

Grey placeholders that hold the shape of content while it loads.

WCAG 2.2 AAStatus: stableNative HTML

Overview

  • Use on first load of the board, backlog and hours.
  • Match the real layout so nothing jumps.

Anatomy

  1. Text line12px.
  2. Title18px, 60%.
  3. CircleAvatar.

Variants

Text, circle, rect.
HTML
<div class="stack" style="width: 16rem;" aria-hidden="true"><span class="skeleton skeleton--title"></span><span class="skeleton skeleton--text"></span><span class="skeleton skeleton--text" style="width: 70%;"></span></div><span class="skeleton skeleton--circle" aria-hidden="true"></span><span class="skeleton skeleton--rect" style="width: 12rem;" aria-hidden="true"></span>

Sizes

Not applicable: Sizes follow the content they replace.

States

Pointer and focus states are forced with data-state so they can be reviewed statically; product code gets them from real pseudo-classes and attributes.

One state: shimmering (static under reduced motion).

Both themes

Responsive behaviour

  • Skeleton layouts follow the same breakpoints as the content.

Theming

The component reads semantic tokens only (listed under Tokens). The dark theme re-maps those tokens; nothing in the component changes.

Accessibility

Role and pattern

Skeletons are aria-hidden; the region has aria-busy="true" and a visually hidden "Loading the board" status.

Keyboard

KeyAction
—Not focusable.

Focus

Not focusable.

Labelling

Announce once for the region, not per block.

Contrast

Shimmer highlight vs base

Motion

Shimmer stops under reduced motion.

Touch

Controls are at least --control-height-md (40px) tall, above the 24px minimum; in dense rows the whole row is also a target and neighbours keep 8px apart.

Content

  • None visible; the hidden status names the region.
