Form field

The wrapper every input uses: label, control, hint, error, counter, in a fixed order.

Overview

  • Every input, select and textarea sits in a .field.
  • Order: label, control, hint, error (error replaces nothing; both can show).

Anatomy

  1. LabelWith required marker.
  2. ControlAny input.
  3. HintFormat or purpose.
  4. ErrorWhat is wrong and how to fix it.

Sizes

Not applicable: The wrapper takes the size of its control.

States

Pointer and focus states are forced with data-state so they can be reviewed statically; product code gets them from real pseudo-classes and attributes.

Responsive behaviour

  • Fields fill their grid cell; labels never sit beside controls below 760px.

Theming

The component reads semantic tokens only (listed under Tokens). The dark theme re-maps those tokens; nothing in the component changes.

Accessibility

Role and pattern

<label for> ties the label; hint and error ids go in the control's aria-describedby; required fields use required and a visible asterisk with aria-hidden.

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the control in DOM order.

Focus

The shared ring (--focus-ring-width solid --color-focus-ring, --focus-ring-offset gap) appears on :focus-visible only. The mocks drew a 25% green halo (rgba(39,103,73,.25)) that measured 1.3:1; the system ring is solid and passes 3:1 (drift D2).

Labelling

One label per control; the error starts with what is wrong.

Motion

No motion beyond colour transitions over --duration-fast, which the tokens zero under prefers-reduced-motion.

Touch

Controls are at least --control-height-md (40px) tall, above the 24px minimum; in dense rows the whole row is also a target and neighbours keep 8px apart.

Content

  • Errors: what is wrong + how to fix: "Enter more than 0 hours."
  • Hints give a format or example.
