Dialog

A modal window for focused tasks: edit a story, plan a sprint, log time, confirm a delete.

Overview

  • Use for a task that must finish or be cancelled before returning (forms, confirmations).
  • Use a page for long, linkable work (the initiative editor).
  • Confirmation dialogs name the object and the loss.

Anatomy

  1. HeadTitle, subtitle, close.
  2. BodyScrolls; --space-6 padding.
  3. ActionsSunken footer, primary last.

Responsive behaviour

  • Below 760px: full width bottom sheet, padding --space-5, actions stack full width.
  • Body scrolls; head and actions stay pinned.

Theming

Component tokens: --dialog-width. Each aliases a semantic token, so a theme re-colours the component by overriding semantic tokens and a product re-skin overrides the component tokens; neither edits the component CSS.

Accessibility

Role and pattern

APG Dialog (Modal): native <dialog> opened with showModal(), which makes the page inert. aria-labelledby the title; confirmations use role="alertdialog" with aria-describedby.

Keyboard

KeyAction
Tab / Shift+TabCycles inside the dialog.
EscCloses (Cancel).
EnterIn a field: submits the form.

Focus

Focus moves to the first field (forms) or the safe button (confirmations) and returns to the trigger on close.

Labelling

Close button named "Close"; the title names the task.

Motion

Fades and rises over --duration-base; reduced motion shows it instantly.

Touch

Controls are at least --control-height-md (40px) tall, above the 24px minimum; in dense rows the whole row is also a target and neighbours keep 8px apart.

Content

  • Title is the task: "Edit story", "Log time".
  • Confirmation title is a question with the object: "Delete QBC-269?"
  • Buttons repeat the verb: "Delete story" / "Keep story".
