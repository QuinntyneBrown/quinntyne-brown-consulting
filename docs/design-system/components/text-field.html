Overview

  • Always inside a form field with a visible label.
  • Use a textarea for descriptions and acceptance criteria.
  • Search fields carry a leading icon and live in toolbars.

Anatomy

  1. Label--text-label.
  2. Input40px, --radius-md, --color-border-strong.
  3. Hint--text-caption, muted.

Responsive behaviour

  • Fields fill their grid column; the form grid collapses to one column below 760px.
  • On phones inputs use 16px text (--font-size-lg) where iOS would otherwise zoom.

Theming

Component tokens: --field-bg, --field-border, --field-height. Each aliases a semantic token, so a theme re-colours the component by overriding semantic tokens and a product re-skin overrides the component tokens; neither edits the component CSS.

Accessibility

Role and pattern

Native <input> with <label for>; hint and error linked with aria-describedby; aria-invalid="true" when wrong; required plus a visible marker.

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the control in DOM order.

Focus

The shared ring (--focus-ring-width solid --color-focus-ring, --focus-ring-offset gap) appears on :focus-visible only. The mocks drew a 25% green halo (rgba(39,103,73,.25)) that measured 1.3:1; the system ring is solid and passes 3:1 (drift D2).

Labelling

Visible label always; placeholder is an example, never the label. Search fields without a visible label use aria-label.

Motion

No motion beyond colour transitions over --duration-fast, which the tokens zero under prefers-reduced-motion.

Touch

Controls are at least --control-height-md (40px) tall, above the 24px minimum; in dense rows the whole row is also a target and neighbours keep 8px apart.

Content

  • Labels are nouns: "Title", "Hours", "Sprint name".
  • Placeholders show a format: "e.g. 1.5".
