## Principles

- **Quiet by default.** White panels, hairline borders and near-black ink. Colour carries meaning — the accent green
  marks the next action and finished work; blue and amber mark workflow state — and nothing else.
- **One primary action per view.** The accent `qbc-button` is the next step; everything beside it is `secondary` or
  `quiet`.
- **The library owns presentation, the app owns behaviour.** `@qbc/components` never imports `@qbc/api`, services or
  feature state, and application templates never use raw `<button>`, `<input>`, `<select>`, `<textarea>`, `<dialog>`
  or `<a>` — `npm run validate:components` enforces both.
- **Native elements underneath.** Every control renders the real HTML element, so keyboard support, forms and assistive
  technology work without re-implementation.
- **Tokens, not values.** Every colour, radius, shadow and shell size is a `--qbc-*` custom property.

## Where the code lives

| Path                                             | Purpose                                                                   |
| ------------------------------------------------ | ------------------------------------------------------------------------- |
| `frontend/projects/components/src/lib/`          | Component source (`<name>/<name>.component.ts`, `.html`, `.scss`)         |
| `frontend/projects/components/src/styles.scss`   | Tokens, reset, focus ring and reduced-motion rule                         |
| `frontend/projects/components/src/public-api.ts` | The public entry point, `@qbc/components`                                 |
| `frontend/projects/components/stories/src/`      | This Storybook: concept and theme MDX, one folder per component, patterns |
| `frontend/projects/components/.storybook/`       | Storybook configuration, manager theme and branding                       |
| `frontend/projects/qbc-workboard/`               | The application that consumes the library                                 |
